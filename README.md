# IFRS 17 Annuity Reserving

Ежемесячный расчет обязательств по договорам пенсионного аннуитета по МСФО 17 (GMM) для страховой компании в Казахстане. Требования — в [PRD.md](PRD.md).

## Быстрый старт (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m demo.generate_demo_data                                   # демо-данные + таблица смертности
.\.venv\Scripts\python.exe -m ifrs17_annuity.cli run-range --from 2024-01 --to 2026-10  # 34 месяца + Excel
.\.venv\Scripts\python.exe -m pytest -q tests                                            # регрессионные тесты
.\.venv\Scripts\streamlit.exe run app.py                                                 # веб-интерфейс
```

Другие команды:

```powershell
.\.venv\Scripts\python.exe -m ifrs17_annuity.cli run --period 2026-11      # закрытие месяца + Excel
.\.venv\Scripts\python.exe -m ifrs17_annuity.cli report --period 2026-10   # только Excel
.\.venv\Scripts\python.exe -m ifrs17_annuity.cli status                    # журнал расчетов
```

Коды возврата CLI: `0` — успех, `1` — ошибка данных или нарушена последовательность месяцев, `2` — не пройдены контроли.

## Подключение к DWH

1. Создайте витрины по шаблону `sql/01_dwh_source_views.sql`.
2. Установите драйвер СУБД (`oracledb`, `pyodbc`, `psycopg2-binary`).
3. В `config/config.yaml` задайте `source.type: dwh`, при необходимости `source.dwh_schema`.
4. Задайте URL подключения в переменной окружения:
   ```powershell
   $env:DWH_URL = "oracle+oracledb://user:password@host:1521/?service_name=DWH"
   ```
5. Для записи результатов в DWH задайте `results_store.url` (или переменную `RESULTS_URL`) и `results_store.schema: ifrs17_res`.

## Методология: ключевые решения

- **Анализ изменений** (period-to-period, B137): 0 → 0a (пересчет по текущим данным DWH) → 1 (проценты) → 2 (ожидаемые потоки) → 3 (фактический состав) → 4 (новые допущения) → 5 (новая кривая) → 6 (новые договоры) → 7 (факт против ожидания).
- **Два трека BEL**: по текущим ставкам и по зафиксированным ставкам каждого договора. Изменения будущей услуги (0a, 3, 4) корректируют CSM по зафиксированным ставкам; разница треков (шаг 4a) и шаг 5 относятся в IFIE. При политике `OCI` накопленный ПСД равен BEL(текущие) − BEL(зафиксированные).
- **Компонент убытка** — часть ООП (не добавляется к BEL+RA+CSM). Его систематическое распределение (п.50(a)) переносит суммы между колонками п.100 и не меняет итог обязательств.
- **Инвестиционный компонент**: выплаты в гарантированный период и выкупные суммы. Отклонение факта от ожидания корректирует CSM (B96(c)).
- **Упрощения MVP**: обременительные новые договоры в группе, у которой уже есть CSM, сначала уменьшают эту CSM. Договор, впервые появившийся в DWH после закрытия месяца заключения, признается в текущем месяце.

## Контроли (по каждой группе в каждом месяце, допуск 0,5 KZT)

1. Роллфорвард п.100 = BEL + RA + CSM; 1b. Роллфорвард п.101 = прямая оценка.
2. Роллфорвард ОВУ = остаток.
3. Δ обязательств = денежные потоки − результат страховых услуг + IFIE.
4. Накопленный ПСД = BEL(тек.) − BEL(зафикс.) (политика OCI).
5. CSM ≥ 0; нет одновременно CSM > 0 и LC > 0; LC ≥ 0.
6. Информационно: пересчет входящего BEL по данным DWH (шаг 0a).

## Ограничения

Таблица смертности, кривая, расходы и шоки RA — демонстрационные. Переход на МСФО 17 не автоматизирован: входящие остатки загружаются в `group_state` за месяц, предшествующий первому расчетному (`ResultStore.load_opening_state`). Финансовые расходы показаны без инвестиционного дохода по активам. Подробнее — разделы 13–14 PRD.
